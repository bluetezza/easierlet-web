## 1. System overview

### 1.1 Product

UK buy-to-let property management for landlords. Native SwiftUI iOS app
for landlords on iPhone/iPad, a public website at
[easierlet.com](https://easierlet.com) with a portal surface that gives
landlords without iOS devices the same management capability and gives
tenants a self-service area. Both share one Supabase backend.

## 2. Database

35 public tables (excluding the PostGIS `spatial_ref_sys` reference table), all with Row Level Security enabled. Two SQL views. PostGIS extension for property geocoding. UUID extension for primary keys.

### 2.1 Conventions

- Primary keys are `uuid` (`gen_random_uuid()` or `uuid_generate_v4()`).
- Every user-owned table has `user_id uuid NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE`.
- Timestamps are `timestamp with time zone` (UTC) — `created_at`/`updated_at` defaulted to `now()` and bumped by trigger.
- Dates are stored as `date`, monetary values as `numeric`, all in GBP (no currency suffix).
- Status enums are CHECK-constrained text columns (cheap to extend; no Postgres enum types in user tables).
- All RLS policies follow the `auth.uid() = user_id` pattern unless the row carries an `access_token` (then a service-role Edge Function does the read on the public's behalf).

### 2.4 PostGIS

- Extension enabled at the database level.
- `properties.location` is a `geography(Point, 4326)` generated column derived from `latitude`/`longitude`. App writes lat/lng, DB maintains location.
- GiST index `idx_properties_location` powers radius queries.
- `nearest_live_listings()` uses `ST_Distance` to sort by proximity.
- `geography_columns` and `geometry_columns` are PostGIS's own catalogue views.
- The PostGIS reference table `spatial_ref_sys` (8500 rows) is the only public table with RLS disabled — that's expected: it's a reference catalogue, not user data.

### 2.5 State machines (cheat sheet)

```
tenants.status:
  draft → invited → awaiting_review → approved → referencing → active → archived
                          ↓
                      rejected

tenancy_agreements.status:
  draft → sent → tenant_signed → landlord_signed → finalised
                                  → cancelled

property_listings.status:
  draft ↔ live → let_agreed → archived
              → delisted

viewing_requests.status:
  pending → proposed → confirmed → completed
              ↓             ↓
          cancelled     no_show

maintenance_requests.status:
  new → acknowledged → awaiting_info → scheduled → in_progress → completed → closed
       → rejected

property_visits.status:
  draft → notice_sent → confirmed → completed
                                  → cancelled

inventory_reports.status:
  draft → sent → completed → locked

landlord_subscriptions.status:
  trialing → active → past_due → expired → cancelled
```

## 3. Edge Functions

36 active functions. All deployed to project `ffzknvcptqjlkxmkdxuk`. Source lives in the swift repo at `supabase/functions/<name>/index.ts`.

`verify_jwt` is the **gateway** setting. Where it's `false`, the function either runs anonymous or does its own JWT validation in code (the "manual JWT check" pattern).

### 3.1 Core lifecycle

#### `tenant-workflow` (v62, JWT)
Application + referencing dispatcher. Actions:
- `get_reference` — public lookup of a reference form by access token
- `submit_application` — public submit of pre-app form
- `send_application`, `send_reference` — email the application link
- `approve_pre_application` — flip tenant to `referencing`, mark reference `approved`, create auth account with temp password, send branded sign-in email
- `references_passed` — flip to `refs_passed`, send invite
- `reject_tenant` — flip to `rejected`, send rejection email (optional reason)
- `get_invite` — public lookup of an invite token for form pre-fill
- `notify_referencing_submitted` (and legacy `notify_vorensys_submitted`)

Writes: `tenants`, `tenant_references`, `profiles`, `audit_log`. Creates Supabase auth users. Sends Resend emails from `no.reply@easierlet.com`.

#### `tenancy-workflow` (v44, JWT or token)
APT tenancy-agreement lifecycle. Actions:
- `get_agreement` — token-authed fetch of agreement + signatures
- `generate_and_send` — generate APT PDF (Housing Act 1988 / Renters' Rights Act 2025 format), insert per-tenant `tenancy_agreement_signatures` rows, email tenants the signing link + the gov.uk "How to rent" info sheet
- `tenant_sign` (token) / `tenant_sign_app` (JWT) — record tenant signature
- `landlord_sign` — record landlord signature
- `finalise` — generate signed PDF, save to `documents`, flip status to `finalised`, activate matching tenants (`tenants.status = 'active'`), email both parties

Writes: `tenancy_agreements`, `tenancy_agreement_signatures`, `documents`, `tenants`. Supabase Storage `documents` uploads. Logs `audit_log`.

#### `inventory-workflow` (v45, JWT or token)
Move-in / move-out report lifecycle. Actions:
- `send` — flip to `sent`, email tenant the review link
- `get_inventory` — token-authed full fetch (rooms + items + signed photo URLs)
- `submit_review` (token) / `submit_review_app` (JWT) — accept tenant's ratings, signature, meter readings
- `notify_landlord` — landlord notification after tenant submission
- `finalise` — generate inventory PDF (with embedded photos at 800px/q70), save to `documents`, lock report

Photo embedding: reads R2 private bucket via presigned GET URLs, downsizes for PDF.

#### `inventory-media-upload` (v3, manual JWT)
R2 photo workflow for inventory_photos. Actions:
- `presign` — 15-min PUT URL; enforces 3 photos/item, 50/inventory caps, 1 MiB/photo
- `confirm` — insert `inventory_photos` row after upload
- `delete` — remove from R2 + DB (only before report is locked)
- `get_signed_urls` — batch convert `r2_key`s to 24-hour read URLs

Dual auth: tenant via inventory access token, OR landlord via JWT.

#### `inventory-media-cleanup` (v3, bearer secret)
Nightly cron. Lists R2 `inventory/` prefix, deletes objects > 24h old with no matching `inventory_photos` row. Capped at 500 deletes per run.

#### `tenant-portal` (v28, service role)
- `send_invite` — creates Supabase auth user for a `tenants` row, links `tenant_auth_id`, sends magic-link email.

#### `tenant-delete-account` (v11, JWT)
- Tenant self-service account deletion. Anonymises `tenants` row per `retention_rules`, deletes auth user, emails landlord.

### 3.2 Listings / public

#### `listing-public-fetch` (v12, no JWT)
GET `?slug=` or POST `{slug}`. Returns `{listing, property, media[]}`. Atomically bumps `view_count`. Used by `/listings/?slug=…`.

#### `listings-search` (v13, anon key + apikey)
Paginated search. Inputs: `area`, `minBedrooms`, `maxBedrooms`, `maxRent`, `minRent`, `availableBy`, `furnished`, `propertyType`, `parking`, `garden`, `petsAllowed`, `sort`, `page`, `pageSize`. Returns results + optional `nearest` fallback when the exact area filter has no matches (uses `nearest_live_listings` RPC).

#### `listing-apply` (v27, Turnstile + token modes)
Cold-apply (slug + Turnstile) or invite (invite_token). Inserts a `tenants` row with `role='pending'` and `application_source`, computes ranking score, emails the landlord.

#### `listing-media-upload` (v21, manual JWT)
Mirrors the inventory media flow for **landlord-side** R2 public bucket:
- `presign` — 15-min PUT URL; size/MIME-type limits per `media_type` (photo 15 MB, photo_360 30 MB, video 150 MB, floorplan 10 MB)
- `confirm` — insert `listing_media` row, optionally set as hero (clears previous hero atomically via partial unique index)
- `update_meta` — change `room_type`, `is_hero`, `room_caption`
- `delete` — remove from R2 + DB

#### `viewing-request` (v22, Turnstile)
Public POST from listing page. Inserts `viewing_requests` with `status='pending'` and an `access_token`. Emails landlord.

#### `viewing-response` (v14, token)
- GET `?token=` — viewer-facing fetch (viewing + property + landlord snapshot)
- POST `{token, action:'accept'|'decline', note?}` — viewer updates status; on accept, generates a `.ics` calendar invite (Apple-iCloud-safe: `METHOD:PUBLISH`, non-Apple `ORGANIZER`, no `ATTENDEE`) and emails both parties.

#### `send-viewing-confirmation` (v20, JWT)
Landlord-side. Generates `.ics`, emails viewer (reply_to = landlord) + landlord.

#### `invite-tenant` (v26, JWT)
Landlord invites a prospect to apply. Creates `tenants` row (`status='invited'`, fresh `invite_token`), emails them the apply link (`/apply-v2/?invite=<token>`).

### 5.7 Site-wide patterns

- **Role-based routing** — `/login/` looks up `profiles.role`; falls back to `tenants.tenant_auth_id` match → tenant; else landlord. `?next=` is honoured only when it points at the role's home, the public site, or a legacy login URL.
- **Portal shell** — every portal page contains `<div id="portal-shell" data-role="…" data-active="…" data-title="…">`. `portal.js` mounts the sidebar + topbar + user menu into it.
- **Tab routing** — pages like `/tenant/` and `/landlord/` use `?tab=` to switch panels without reload. `[data-tab-panel="…"]` toggles `display:none/block`.
- **Cache-busting** — CSS/JS links carry `?v=YYYYMMDDx`. Bumped on each deploy.
- **PostgREST via authed fetch** — same RLS as iOS; the JWT in the user's session is the only thing scoping queries. No separate auth model.

### 7.6 Conventions

- All times UTC in the DB; UI renders with `en-GB`.
- All monetary values `numeric` in DB, no currency suffix.
- All status enums are CHECK constraints, not Postgres `enum` types — easier to evolve.
- Edge Functions called from web use `ELP.callFn(name, body)` (auto-attaches the user JWT and the anon key).
- Edge Functions called from iOS use a custom `URLSession` wrapper that attaches the JWT and the `apikey` header.
- Tokens for token-based flows are columns on the row they protect (`access_token`, `signing_token`, `invite_token`). No JWTs are issued separately.
- RLS is enforced everywhere — Edge Functions that need to read across users use the service-role key explicitly.

### 7.7 Known things to keep in mind

- **`spatial_ref_sys` has RLS disabled** — that's expected; it's the PostGIS reference catalogue. Not actionable.
- **Magic-link emails are server-generated by Supabase** — make sure the email template at Supabase Auth → Email Templates points back at `https://easierlet.com/login/` (or the corresponding domain you're testing on).
- **R2 public URLs** — `https://media.easierlet.com/listings/…` is served via Cloudflare from the R2 public bucket. The `R2_PUBLIC_URL_BASE` env var on Edge Functions is the source of truth for that prefix.
- **Listing slugs** are immutable once a listing goes `live`. Existing legacy address-based slugs are not migrated to the new 7-char base58 format (would break shared links).
- **Tenant role flow**: every applicant enters as `role='pending'`. Landlord assignment to `lead` is enforced by a partial unique index on `(property_id) WHERE role='lead' AND status NOT IN ('active','archived')`.
- **Joint tenancy** uses multiple rows in `tenancy_agreement_signatures` per `tenancy_agreements` row, each with its own `signing_token`.
- **Audit log** grows unbounded — has indexes on actor + action + resource. Worth periodic archival in production.
